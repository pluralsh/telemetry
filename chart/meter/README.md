# Meter Helm chart

This chart deploys Meter in exactly one of two topologies:

- `standalone`: one StatefulSet replica. The replica count is intentionally not
  configurable because multiple standalone processes must not concurrently own
  the same store.
- `sharded`: a writer StatefulSet with stable pod identities and a reader
  StatefulSet. Meter uses the Kubernetes API to derive writer membership,
  publishes contiguous range assignments through a watched ConfigMap, and
  protects each independently writable shard with a stable, watched Lease.

## Install

```sh
helm install meter oci://ghcr.io/pluralsh/charts/meter \
  --version 0.1.0 \
  --namespace telemetry \
  --create-namespace
```

For sharded operation, use a shared object store and enable an internal token:

```yaml
mode: sharded

config:
  storage:
    path: production
    object_store:
      type: Aws
      region: us-east-1
      bucket: my-meter-bucket
    block_cache:
      type: FoyerHybrid
      memory_capacity: 536870912
      disk_capacity: 10737418240
      disk_path: /var/cache/meter
    meta_cache:
      type: FoyerMemory
      capacity: 134217728

internalToken:
  enabled: true
  existingSecret: meter-internal-token
  key: token

extraEnvFrom:
  - secretRef:
      name: meter-object-store
```

The referenced token is mounted as a read-only file. It is not copied into the
generated ConfigMaps. Alternatively, set `internalToken.value` and let the chart
create the Secret; using an externally managed Secret is recommended.

## Configuration

The chart's `config.*` values render the corresponding server configuration into
role-specific ConfigMaps. See the [complete Meter YAML reference](../../config/README.md)
for field semantics, defaults, units, cache/object-store variants, authentication,
and namespace behavior.

The most important values are:

- `mode`: `standalone` or `sharded`.
- `writer.replicas` / `reader.replicas`: sharded workload sizes.
- `config.storage`, `config.write`, `config.auth`, and
  `config.namespaces`: Meter server configuration.
- `sharding.*`: shard count, I/O concurrency, and Kubernetes lease timing settings. Resource
  names are generated by the chart and cannot drift from rendered resources.
- `persistence`: data volume settings. With persistence disabled, an `emptyDir`
  is mounted at `persistence.mountPath`.
- `cache.persistence`: cache volume settings. With persistence disabled, an
  optionally sized or memory-backed `emptyDir` is used.
- `extraEnv`, `extraEnvFrom`, `extraVolumes`, and `extraVolumeMounts`: additions
  applied to every Meter pod.
- `podSecurityContext`, `securityContext`, `resources`, scheduling values, and
  probe settings: workload hardening and placement.

The default local object store is suitable for a single standalone pod. Sharded
deployments must configure storage shared by every writer and reader, such as
S3. A PVC mounted independently into each StatefulSet pod is not shared object
storage unless the selected storage class and object-store configuration
explicitly provide that behavior.

`config.auth.unauthenticated` defaults to `false`, so namespace read/write HTTP
APIs require valid Basic or JWT credentials. Empty credential lists do not open
access. Health and readiness endpoints remain public. Set the value to `true`
only when anonymous namespace access is intentional.

### JWT/JWKS

For a file JWKS, create a Secret containing the public JWKS document and mount
it into every Meter pod. The chart does not copy JWKS contents into a ConfigMap:

```yaml
config:
  auth:
    unauthenticated: false
    jwt:
      jwks:
        source: file
        path: /var/run/secrets/meter-jwks/jwks.json
      issuer: https://issuer.example/
      audience: meter
      refresh_interval_seconds: 300
      request_timeout_seconds: 5
    global:
      read: []
      write: []

extraVolumes:
  - name: jwt-jwks
    secret:
      secretName: meter-jwt-jwks
extraVolumeMounts:
  - name: jwt-jwks
    mountPath: /var/run/secrets/meter-jwks
    readOnly: true
```

The referenced Secret must have a `jwks.json` key. File JWKS data is loaded
once when each process starts, so rotate it by restarting/rolling the pods.
For a URL source, set `jwks: { source: url, url: ... }` and do not add a volume;
Meter fetches it at startup and refreshes it according to the server
configuration. JWTs authorize external HTTP routes only. `internalToken` is a
separate writer-to-writer gRPC credential.

## Services and RBAC

Standalone mode creates an HTTP/gRPC Service and a governing headless Service.
Sharded mode creates writer and reader HTTP/gRPC Services plus the writer
headless Service used for stable owner DNS.

In sharded mode, the chart creates namespace-scoped RBAC for Meter's assignment
ConfigMap, coordination Leases, and writer StatefulSet membership. Set
`serviceAccount.create=false`, `serviceAccount.name`, and `rbac.create=false`
when supplying equivalent resources externally.

`POD_NAME` and `POD_NAMESPACE` are injected from the downward API in every pod.

## Validation

```sh
helm lint ./chart/meter
helm template meter ./chart/meter --namespace telemetry
helm template meter ./chart/meter --namespace telemetry --set mode=sharded
```
